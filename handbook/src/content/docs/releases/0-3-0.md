This public beta is the cumulative update for testers moving from **the 2026-10-30 public beta (0.2.8)
to 0.3.0**. iOS and Android cover the same release window; their store build
numbers differ. It is a new version, so the first external TestFlight build of
0.3.0 goes through TestFlight Beta App Review before testers can install it.

Live streaming and Multiview are new in this version and have not been tested on
camera hardware yet. See [Availability and remaining limits](#availability-and-remaining-limits).

## iOS

### iOS: new and changed

- Live stream the monitor picture to Twitch, YouTube, Facebook, Instagram or a Custom server. Set it up in **Settings → Sharing → Live stream** (the stream key is kept in the keychain), then tap **Go live** under the timecode at the top right. One confirmation starts the stream and one stops it; while live, a red LIVE pill shows the elapsed time with one status line under it. The stream carries the clean picture (with the monitor LUT when it is on, never the assists) and the phone's microphone, asked for only after you confirm. A Custom server may be plain `rtmp://` (for TikTok LIVE) with a warning.
- Streaming works over USB-C, HDMI capture, a shared Wi-Fi network or the phone's hotspot. On the camera's own Wi-Fi, Go live is off and says why. When the camera picture is smaller than 1080p, the Quality row offers **1080p upscaled** beside **Camera feed**. Leaving the app ends the stream; with the monitor closed, a Live pill at the top keeps Stop in reach.
- [Multiview](../../guides/multiview/) is now the same stage as OpenPocketCine's. Tap the grid icon in **Your cameras**, then add up to four Z bodies that are already on a router or the phone's hotspot. Tiles show picture, battery, card space, timecode and recording state, with a settings popup for the Live View values. Auto LUT follows each body's recording tone, record starts every body or none, and a double tap opens a body in Live View without a new connection.
- **Settings → Controls** opens with **Camera presets**: save the connected camera's exposure and white balance under a name, recall it later or delete it. Values the camera cannot take right now are listed as skipped. Presets are kept per camera model.
- **GUIDES** add **Action safe** and **Title safe**, each with its own size (50% to 99%, default 90% and 80%), drawn inside every frame line on live view and playback. Both start off.
- The monitor's lock button also holds the screen rotation, upside-down landscape included, so a phone mounted inverted no longer flips when it is levelled.

### iOS: fixes

- In N-Log, the highlight zebra can be set above the camera's white, for example 245 in 0-255 units to match the camera, instead of stopping at 234. Midtone and the IRE scale are unchanged.
- VoiceOver no longer reads the monitor's header readouts twice.

### iOS: what to test

- Save a stream key, then Go live over USB-C, a shared Wi-Fi network or the phone's hotspot. Check that the stream plays on the service and Stop ends it. On the camera's own Wi-Fi, Go live should say why it is off. Try a Custom `rtmp://` server and **1080p upscaled**.
- Join two or more bodies to the phone's network, open Multiview, add them and record. Double-tap a tile for Live View and return. Use **Share Diagnostics** if a tile drops.
- Save a camera preset, change those values on the camera, then recall it. Check the skipped list in a mode where a value cannot be set.
- Turn on Action safe and Title safe, change their sizes and check them on live view and playback. Lock the monitor upside down and level the phone.
- In N-Log, set the highlight zebra to 245 in 0-255 units and check that only the brightest highlights stripe.

## Android

Google Play's short notes for this release (the phone and Wear OS share them):

- New: live stream the monitored camera to YouTube, Twitch, Facebook, Instagram or your own server. Not yet tested on a real stream.
- New Multiview: up to four Z bodies on one screen. Not yet tested on camera hardware.
- Camera presets for exposure and white balance, Action safe and Title safe guides, and the lock holds rotation.
- USB-C retries once when the camera's first reply fails.
- Highlight zebra can go above N-Log white.

The iOS lists above describe the same shared behavior in more detail. On
Android, Go live and the Live pill work the same way, a stream ended by leaving
the app offers Restart, and an HDR live picture is not streamed yet (the stream
keeps the last SDR frame). The VoiceOver fix is iOS only.

### Android: fixes

- A USB-C connect whose first read from the camera fails early now clears the stalled connection once and retries, within the same connect time limit. **Share Diagnostics** records whether the read timed out or failed. This targets a Z 6III that failed every USB-C connect; if it still fails, send diagnostics.

## Availability and remaining limits

- Live streaming has not streamed to a real service from a phone yet, on either platform.
- Multiview has not been tested on Z bodies yet ([details](../../guides/multiview/)).
- Camera presets, the safe-area guides, the rotation hold, the zebra change and the Android USB-C retry are untested on camera hardware.

The previous window is in the [0.2.8 notes](../0-2-8/).
